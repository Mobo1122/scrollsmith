  <action>
Create Railway configuration files for deployment:

1. Create `backend/railway.json`:
   ```json
   {
     "$schema": "https://railway.app/railway.schema.json",
     "build": {
       "builder": "NIXPACKS",
       "buildCommand": "pip install -r requirements.txt"
     },
     "deploy": {
       "startCommand": "alembic upgrade head && uvicorn app.main:app --host 0.0.0.0 --port $PORT",
       "restartPolicyType": "ON_FAILURE",
       "restartPolicyMaxRetries": 10
     }
   }
   ```

2. Create `backend/Procfile` (alternative Railway start command format):
   ```
   web: alembic upgrade head && uvicorn app.main:app --host 0.0.0.0 --port $PORT
   ```

Why run migrations on startup: Ensures database schema is always up-to-date with code. Railway injects $PORT automatically. Running migrations before uvicorn prevents schema mismatch errors.

Important: The start command MUST run migrations first (alembic upgrade head) then start the server. This ensures database schema matches the deployed code version.

<task type="auto">
  <name>Task 2: Deploy to Railway and configure environment</name>
  <files>
backend/.env (Railway environment variables)
  </files>
  <action>
Deploy backend to Railway using Railway CLI:

1. Install Railway CLI if not present:
   ```bash
   brew install railway
   ```

2. Login to Railway:
   ```bash
   railway login
   ```

3. Initialize Railway project (creates railway.toml):
   ```bash
   cd backend
   railway init
   ```

4. Add PostgreSQL database to project:
   ```bash
   railway add --database postgresql
   ```
   This automatically injects DATABASE_URL environment variable.

5. Link the Railway service:
   ```bash
   railway link
   ```

6. Set additional environment variables:
   ```bash
   railway variables set ENVIRONMENT=production
   ```

7. Deploy the backend:
   ```bash
   railway up
   ```

8. Get the deployment URL:
   ```bash
   railway domain
   ```
   This generates a public HTTPS URL like: scrollsmith-backend-production-xxxx.up.railway.app

9. Verify deployment logs:
   ```bash
   railway logs
   ```
   Check for "Alembic upgrade head" success and "Uvicorn running on" messages.

Why Railway: Research identified Railway as ideal for FastAPI deployment with automatic PostgreSQL provisioning, built-in environment variable management, and HTTPS. Auto-deploy on git push provides continuous deployment.

Note on DATABASE_URL: Railway automatically injects this when PostgreSQL add-on is created. No manual configuration needed. The connection string uses the correct postgresql+asyncpg:// format for async SQLAlchemy.
  </action>
